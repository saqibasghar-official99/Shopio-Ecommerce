# Shopio-Ecommerce

## Seller programme

The seller portal is available at `/seller`; applications are submitted at `/seller/register` and must be approved in **Admin → Sellers** before product, order, earning, and reward features are enabled. Seller accounts use a dedicated JWT cookie and do not share customer or administrator sessions.

Referral links use `?ref=CODE` and first-touch attribution for 30 days. Attribution is resolved on the server when checkout creates an order; only a currently approved seller can be attributed, and self-purchases are excluded. Commission rates are snapshotted when an order is created, so later rate changes affect new orders only. Commissions are calculated from catalogue prices capped by the net merchandise amount after discounts, excluding delivery, and remain pending until an order is delivered and payment is confirmed. Cancelled, failed, and fully refunded orders reverse commission; partial merchandise refunds reduce unpaid commission proportionally. A refund on a previously paid-out commission flags it for admin dispute review rather than silently clawing back a completed payout. Rewards count distinct delivered/paid referred orders with some net merchandise remaining in the order-creation calendar month in Asia/Karachi; each configured threshold unlocks one gift up to the configured monthly cap.

Gift Boost gifts live in a separate `SellerGift` collection and are never included in customer product catalogue queries. Stock is reserved using a MongoDB transaction when a seller claims a gift. MongoDB must support transactions (for example, a replica set) for concurrent claim protection.

In Seller Dashboard → Products, **Place for Customer** creates a regular `Order` through `POST /api/orders`; it is not a separate seller-order store. The server verifies approval, product price, variants, stock, customer details, and an active delivery zone. Seller-entered selling price, Veeo's price, and per-unit profit are snapshotted on the order line. COD is currently the only supported seller order method; the order total and delivery fee are printed as the COD amount on Veeo's shipping label. Stock is reserved for these seller-created orders and restored if the order is cancelled or marked payment-failed. Seller profit remains pending until an administrator records both delivery and confirmed payment; refunds and cancellations reconcile the same earnings ledger used by seller payouts.

**COD/courier limitation:** this repository has no courier booking, COD collection, or courier remittance integration. The shipping label is printable only and displays the amount the courier should collect; it does not transmit or confirm that amount with a carrier. Admin must reconcile courier statements and confirm payment manually. Do not treat seller profit as payable or launch automated seller-order COD operations until the selected courier's collection and remittance process has been verified and integrated.

### Seller deployment setup

- Configure `SELLER_JWT_SECRET` as a random secret with at least 32 characters. Seller login fails closed if it is absent.
- Configure `GMAIL_USER` with the Gmail address used to send seller verification emails and `GMAIL_APP_PASSWORD` with that account's Google App Password. Keep both values server-side in `.env.local` for local development and in the deployment platform's secret environment-variable settings; never prefix them with `NEXT_PUBLIC_`.
- New seller applications must verify their email with the six-digit code sent during registration. Codes are stored as keyed hashes, expire after five minutes, allow five incorrect attempts, and can be resent after a 60-second cooldown up to three times per 15-minute window. New seller accounts are automatically approved after 60 seconds by a Netlify scheduled function that runs every minute; seller requests also apply overdue approvals if scheduled execution is delayed. Existing pending applications are not changed.
- Sellers who forget their password can request a password-reset code from the seller sign-in page. Reset codes are emailed only to verified seller accounts, are stored as keyed hashes, expire after five minutes, allow five incorrect attempts, and are limited to three sends per 15-minute window with a 60-second cooldown. The request response does not reveal whether an email belongs to a seller.
- To test locally, add `GMAIL_USER=your-gmail-address` and `GMAIL_APP_PASSWORD=your-16-character-app-password` to `.env.local` alongside `SELLER_JWT_SECRET`, restart `npm run dev`, submit a new application at `/seller/register`, and enter the code delivered to that inbox. Successful verification creates the seller session; if the scheduled approval has not run yet, the application-pending state is shown until the seller is approved. Test login with the same account, and test the resend button after its cooldown.
- To test password recovery, sign out, open `/seller/login`, choose **Forgot password?**, request a code, and submit the emailed six-digit code with a new password. Confirm the new password works on the next sign-in; request another code to test resend throttling.
- Configure commission rates and reward limits in **Admin → Sellers**; the default commission rate starts at `0` until the administrator configures a rate. The default reward threshold is 3 qualifying orders/month and the gift cap is 2/month.
- After deploying model changes, run `npm run ensure-indexes` to build the seller, order-attribution, commission, gift, claim, payout, and audit indexes.
- Sellers can change passwords while signed in; account recovery must be handled through Veeo support.
